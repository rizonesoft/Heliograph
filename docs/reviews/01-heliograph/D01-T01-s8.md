The plan needs changes before implementation. The highest-impact gap is in CLI dispatch: adding `landed` to the command table exactly as proposed can make it **refuse the job**. The archive protocol also permits a caller to receive exit 2 for a mark that was successfully archived.

An appended command falls through to `store_end(..., which == 6, note)`, which selects refusal and passes the commit as its note. Call `store_landed` explicitly. The archiver copies the mark and removes the live post. The proposed writer then returns “it was archived,” although the archive permanently contains its mark. A second authorized caller can also observe `P_EXISTS`, return success while the post is still live, and then lose the mark when the first writer rolls it back. Evidence: traced. The archive collects event names before copying and collects them again after unlink. `live_post` tests only the live post, and `remove_event` treats an already-absent file as success. Define one outcome for both publishers and archivers: an acknowledged mark must survive, and an exit-2 refusal must not introduce an archived mark. Cover publication before and after the archive scan, a same-commit collision, and process death before the second look.
